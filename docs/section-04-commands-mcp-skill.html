기초 커맨드 -- 치트시트

커맨드기능언제 쓰나
/help전체 명령어 목록뭐가 있는지 모를 때
/context현재 토큰 사용량 확인"지금 얼마나 썼지?"
/clear컨텍스트 초기화새로운 작업 시작할 때
/compact대화 요약 후 압축컨텍스트 꽉 찼을 때
/initCLAUDE.md 자동 생성새 프로젝트 시작할 때
/permissions도구 허용/차단 관리반복 승인 귀찮을 때
/btw메인 작업을 방해하지 않고 질문"이거 왜 이렇게 동작해?"

가장 자주 쓰는 3개: /clear, /compact, /context

/btw -- 메인 작업을 방해하지 않는 질문

# Claude가 코드를 수정하는 중간에: /btw 이 함수에서 왜 Date 객체 대신 문자열 비교를 쓴 거야? # Claude는 현재 작업을 계속하면서 질문에 답변
  • 메인 작업을 중단하지 않음
  • 현재 세션에서 진행 중인 작업에 대해 질문
  • 작업 흐름을 깨지 않고 궁금한 점을 바로 확인

커스텀 Skill -- "반복 작업을 재사용 가능하게"

  • 반복하는 작업 패턴을 재사용 가능한 형태로 등록
  • .claude/skills/ 디렉토리에 SKILL.md 파일로 정의
  • 팀원 모두가 같은 스킬을 공유
호출 방식예시동작
수동 호출/review src/api/tasks/route.ts슬래시 커맨드로 직접 실행
자동 호출"이 파일 리뷰해줘"description 매칭으로 자동 실행

매번 긴 프롬프트 대신 → /review src/app/api/tasks/route.ts 한 줄로

참고: Anthropic 공식 스킬 레포지토리 (pdf, frontend-design, claude-api, skill-creator 등 17개 공식 스킬)

SKILL.md 구조

SKILL.md = frontmatter + 자유 형식 본문

--- name: review description: 코드 파일을 리뷰하여 버그, 보안, 성능 문제를 찾는다 --- $ARGUMENTS 파일을 아래 관점으로 리뷰한다. ## 리뷰 관점 1. 버그 -- 로직 오류, 엣지 케이스 누락 2. 보안 -- 인젝션, 인증 누락 3. 성능 -- 불필요한 연산, N+1 쿼리 ## 출력 형식 심각도별로 정리: Critical / Warning / Info
  • frontmatter: name, description (자동 호출 매칭 기준)
  • 본문: Claude에게 주는 지시문 (자유 형식)
  • $ARGUMENTS: 사용자 입력이 치환되는 자리

Skill 실행 흐름

사용자: /review src/app/api/tasks/route.ts | v SKILL.md: $ARGUMENTS = "src/app/api/tasks/route.ts" | v Claude: 1. 해당 파일 읽기 2. 리뷰 관점 4가지로 분석 3. 심각도별 정리해서 출력 | v 결과: Critical: assigneeId가 Prisma create에 누락됨 Warning: 에러 응답에 상세 메시지 없음 Info: status 유효값 검증 추가 권장

같은 Skill = 같은 형식의 결과 → 팀원 누구나 동일한 리뷰를 받음

MCP -- "Claude에 USB 포트를 다는 것"

  • Claude Code 혼자서는 브라우저 제어, 외부 서비스 연동 불가
  • MCP = 외부 도구와 Claude를 연결하는 표준 프로토콜
  • USB 포트에 장치를 꽂듯이, 필요한 도구를 연결

MCP 설치 -- 한 줄이면 끝

# Chrome DevTools 연결 (로컬 stdio) claude mcp add chrome-devtools --scope project npx chrome-devtools-mcp@latest # Playwright 브라우저 자동화 (로컬 stdio) claude mcp add playwright --scope user npx @playwright/mcp@latest # Notion 연결 (리모트 HTTP) claude mcp add --transport http notion https://mcp.notion.com/mcp

두 가지 연결 방식:

  • --scope user + npx = 로컬 stdio 서버 (내 PC에서 실행)
  • --transport http + URL = 리모트 HTTP 서버 (클라우드)

공식 문서: Chrome DevTools MCP · Playwright MCP · Notion MCP

MCP는 2-3개만 설치 -- 각 MCP가 컨텍스트를 소비합니다

MCP vs CLI -- 최근 흐름

MCPCLI
설치MCP 서버 설치 필요이미 있는 CLI 도구 사용
컨텍스트 비용도구 목록이 토큰 차지없음
장점구조화된 입출력, 안정적가볍고 유연, 도구 무한
적합한 경우반복적 외부 연동일회성 호출, 간단한 작업
# MCP 방식: Playwright MCP 설치 후 "이 페이지 스크린샷 찍어줘" → Claude가 Playwright 도구 사용 # CLI 방식: 설치 없이 "curl로 이 API 호출해줘" → Claude가 직접 curl 실행

2 TaskFlow 실행 후 브라우저에서 localhost:3000 열기

TaskFlow 앱에서 새 업무를 만들어봐. 담당자를 "김개발"로 선택하고 생성한 후, 네트워크 탭에서 POST 요청의 body와 응답을 확인해줘.

같은 버그, 2가지 관점

/review (Skill) Chrome DevTools (MCP) ---------------- --------------------- 관점: 코드 분석 브라우저 동작 발견: "assigneeId 누락" "응답에 null" 방법: 정적 분석 동적 관찰 | | +------ 같은 버그 -------+

Skill → 코드를 읽고 문제를 찾음 (정적 분석)

DevTools → 실행 중인 앱을 관찰 (동적 검증)
