Claude Code 셋업

설치 가이드: code.claude.com/docs/en/setup

bash # macOS / Linux (권장 — 자동 업데이트 포함) curl -fsSL https://claude.ai/install.sh | bash # 또는 Homebrew brew install --cask claude-code # 확인 claude --version

프로젝트 인식 과정

  • 1 claude 실행 → 현재 디렉토리를 프로젝트 루트로 인식
  • 2 CLAUDE.md → 팀 규칙 로딩, .claude/settings.json → 설정 로딩
  • 3 대화 시작 후, 필요에 따라 package.json 등 프로젝트 파일을 도구로 읽어 스택 파악

컨텍스트 윈도우 = 작업 책상

여러분의 책상 크기가 정해져 있다고 상상하세요. 서류를 올릴수록 공간이 줄어들고, 가득 차면 아래에 깔린 서류는 찾을 수 없습니다.

┌─────────────────────────────────────────┐ │ 시스템 프롬프트 ~6% │ │ CLAUDE.md ~2% │ │ MCP 도구 목록 ~5~20% │ │ ───────────────────────────────── │ │ 대화 이력 + 읽은 파일 ← 여기가 채워짐 │ │ │ │ 남은 공간 ← 이게 줄어듦 │ └─────────────────────────────────────────┘ Opus: 1M 토큰 / Sonnet: 200K 토큰

진짜 쓸 수 있는 공간은 생각보다 적다!

매 프롬프트 = 전체 전송

프롬프트를 보낼 때마다,
지금까지의 모든 대화 내용이 통째로 전송됩니다.

[1번째] → 시스템 + 메시지1 (작음) [2번째] → 시스템 + 메시지1 + 응답1 + 메시지2 (커짐) [3번째] → 시스템 + 메시지1 + 응답1 + 메시지2 + 응답2 + ... (더 커짐) ... [N번째] → 시스템 + 전체 대화 이력 + 메시지N (매우 큼!)
  • 대화가 길어질수록 매번 보내는 양이 기하급수적으로 증가
  • 토큰 비용 = 누적 (이전 대화를 계속 다시 보냄)
  • 세션이 길수록 → 느려지고, 비싸지고, 부정확해짐

컨텍스트 관리 3대 명령어

명령어비유용도
/context"책상 상태 확인"지금 얼마나 차 있는지 확인
/clear"책상 완전히 치우기"작업 전환 시 반드시 실행
/compact"서류를 요약 메모 한 장으로"같은 작업 이어갈 때 압축
demo /context # → Context window usage: (Opus 1M 기준) # System prompt: 60,000 tokens (6%) # Conversation: 230,000 tokens (23%) # Available: 710,000 tokens (71%)
  • 70% 넘으면 → /compact로 압축
  • 작업 바뀌면 → /clear로 초기화
  • 습관: 작업 전환 = /clear

"Kitchen Sink Session" 안티패턴

나쁜 패턴 (한 세션에서 이것저것)

claude 실행 → 버그 수정 → 새 기능 추가 → 테스트 작성 → 문서 작성 → 리팩토링 → ... (컨텍스트 오염)

좋은 패턴 (작업 전환마다 /clear)

claude → 버그 수정 → /clear claude → 새 기능 추가 → /clear claude → 테스트 작성 → /clear

핵심 원칙: 한 번에 한 가지 일.

프롬프팅 팁

상황프롬프트 예시
파일 위치를 아는 경우src/components/TaskList.tsx에서 completed 필터 선택 시 미완료 업무가 보여
증상만 아는 경우필터를 "완료"로 바꿔도 미완료 항목이 계속 보이는 버그가 있어. 원인 찾아줘
뭔가 이상한데 모르겠는 경우할일 목록 페이지에서 뭔가 이상해. Plan 모드로 코드 읽고 문제 분석해줘

실패하는 프롬프트

  • "버그 고쳐줘" → 뭘 고치라는 건지 모름
  • "코드 개선해줘" → 어떤 방향으로?
  • "전체 리팩토링해줘" → 범위가 너무 넓음

잘 되는 프롬프트

  • 관찰한 증상이 있다
  • 완료 조건이 있다
  • 2회 실패하면 /clear 후 다시 시도

프롬프팅 -- 추가 입력 방법

방법사용법추천 상황
@파일 참조@src/lib/utils.ts 이 함수 설명해줘특정 파일을 컨텍스트에 추가
이미지 붙여넣기드래그앤드롭 또는 Ctrl+V에러 스크린샷 전달
파이프 입력npm run dev 2>&1 | claude "분석해줘"빌드 에러, 로그 분석
-p 플래그echo "질문" | claude -p대화 없이 1회성 답변

주의: @파일을 많이 참조하면 컨텍스트가 빨리 찬다. 꼭 필요한 파일만!

권한 모드 — Claude에게 얼마나 맡길 것인가

전환: Shift+Tab으로 순환 — default → acceptEdits → plan → auto

모드동작사용 시점
default파일 읽기는 자유, 편집/명령은 매번 확인처음 사용하거나 민감한 코드 작업 시
acceptEdits파일 편집 + 기본 명령(mkdir, rm 등) 자동 승인.
Bash 실행/네트워크는 여전히 확인		신뢰할 수 있는 작업, 빠른 편집 시
plan코드를 읽기만 함. 수정/실행 안 함탐색, 계획, 방향 잡기
auto 2026.03~AI 분류기가 매 작업을 평가 — 안전하면 자동 승인,
위험하면 차단 후 대안 시도		장시간 작업, 최소 개입
dontAskpermissions.allow 규칙에 매칭되는 것만 실행,
나머지는 프롬프트 없이 거부		CI/CD 파이프라인, 자동화 스크립트
bypassPermissions모든 권한 검사 비활성화. 확인 없이 전부 실행컨테이너/VM 전용 — 호스트 금지

bypassPermissions = 구 --dangerously-skip-permissions 플래그의 후속. 모든 검사를 건너뛰므로 rm -rf ~/ 같은 명령도 그대로 실행됨. auto 모드가 이를 대체하는 안전한 대안 — 분류기가 위험한 작업을 사전 차단

Plan Mode — 가장 중요한 모드

Boris Cherny (Claude Code 창시자):

"Don't keep pushing when things go sideways — switch back to plan mode and re-plan."

"일이 꼬이면 밀고 나가지 말고, Plan Mode로 돌아가서 다시 계획을 세워라."

Plan First 워크플로우 (R.P.I) ① [Plan] "이 버그를 고치려면 뭘 확인해야 해?" Research ② [Plan] "이 방향으로 수정할 건데 맞아?" Plan ③ [일반] "계획대로 수정하고 테스트 돌려" Implement ④ 결과가 이상하면 → 즉시 Plan Mode로 복귀 Re-plan

바로 실행하면

잘못된 방향으로 수십 개 파일 수정 → 되돌리기 어려움 + 컨텍스트 낭비

Plan 먼저 하면

코드를 안 건드리니 깨끗한 상태에서 방향 수정 → 1-shot 실행
