main → 프롬프팅 → CLAUDE.md → Skill+MCP → Hooks → 플러그인 → 에이전트 → 하네스 → Spec Driven 섹션 1 Claude Code가 뭔지 봤다 섹션 2 프롬프트 품질 = 결과 품질 섹션 3 CLAUDE.md로 일관된 코드 스타일 섹션 4 Skill로 반복 작업 자동화 + MCP로 외부 연결 섹션 5 Hooks로 안전장치 + 자동화 섹션 6 플러그인으로 토큰 절약 + 생산성 섹션 7 커스텀 에이전트로 전문가 팀 구성 섹션 8 에이전트 팀을 하네스로 완성 섹션 9 Spec Driven으로 계획 먼저, 구현은 나중에

'빈 프로젝트' → 'Claude Code Ready 프로젝트'

섹션별 핵심 한 줄 요약

섹션핵심 한 줄키워드
1읽고, 편집하고, 실행하는 에이전트에이전틱 코딩
2컨텍스트는 작업 책상. /clear 습관화프롬프팅 공식
3CLAUDE.md = 프로젝트의 기억. 200줄 이내팀 규칙 공유
4반복 작업 → Skill, 외부 도구 → MCP자동화
5안내문(CLAUDE.md) vs 자동문(Hooks)강제 규칙
6플러그인 하나로 전부 설치RTK = 토큰 절약
7역할을 나누면 품질이 올라간다서브에이전트
8AI는 확률적이지만 환경을 잡으면 일관된다하네스
9"바로 해" 보다 "계획 세워"가 빠르다R.P.I

하나만 기억한다면 → "환경을 잡으면 일관된다"

내일부터 할 일 3가지

1 자기 프로젝트에 CLAUDE.md 만들기

/init으로 시작, 팀 규칙 200줄 이내로 추가

효과: 즉시 코드 품질 향상

2 반복 작업 하나를 Skill로 만들기

코드 리뷰, 커밋 메시지, 테스트 작성 중 택 1

효과: 매일 10분 절약

3 RTK 설치해서 토큰 아끼기

curl 한 줄 + rtk init -g

효과: 토큰 60-90% 절약

토큰 절약 핵심 5선

  • API 생성 + DB 마이그레이션
  • Serena MCP로 대규모 코드베이스 탐색

흔한 실수 5가지

1 한 세션에 모든 작업

→ /clear로 작업 전환, 컨텍스트 초기화

2 CLAUDE.md 500줄 장편

→ 200줄 이하, 핵심 규칙만

3 MCP 5개 설치

→ 2-3개 + 필요 시 추가, Tool Search 활용

4 결과 검증 없이 신뢰

→ "테스트 포함" 프롬프트, 항상 검증

5 모호한 프롬프트 반복

→ [파일 경로] + [구체적 증상] + [검증 방법]
