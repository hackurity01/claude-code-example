커스텀 에이전트
& 오케스트레이션

역할을 나눠 품질을 높이고, 팀으로 연결해 자동화한다

Claude 한 명이 전부 다 한다면

"이 파일 리뷰하고 테스트 작성하고 문서도 만들어줘" Claude가 하는 일: 1. 파일 구조 파악 (컨텍스트 소비) 2. 코드 리뷰 (컨텍스트 소비) 3. 테스트 작성 (컨텍스트 더 소비) 4. 문서 작성 (컨텍스트 거의 풀) 5. ...앞에서 뭘 지시했더라?

뒤로 갈수록 품질 하락

리뷰는 꼼꼼, 테스트는 대충, 문서는 빠뜨림

결과물이 매번 다름

같은 요청인데 매번 다른 포맷

해결책 — 역할을 나누자

한 명이 다 하는 대신: code-reviewer → "이 파일의 버그와 보안만 봐" test-writer → "이 이슈에 대한 테스트만 써" doc-writer → "이 변경을 문서로 정리해" 각자 전문화된 지시 아래 한 가지에만 집중 → 품질 ↑ 일관성 ↑ 재현 가능성 ↑

Boris의 접근법: 에이전트는 하나의 거대한 에이전트가 아니라 모듈화된 역할이다. 신뢰성은 전문화와 제약에서 나온다.

서브에이전트 — 컨텍스트를 보호하는 기술

일반적인 사용

"인증 관련 파일을 전부 찾아 분석해줘"

→ 메인 컨텍스트에 수십 개 파일 내용이 쌓임

서브에이전트로 위임

Claude가 별도 컨텍스트에서 조사

→ 요약만 메인에 반환, 컨텍스트 깨끗 유지

서브에이전트 = 별도의 작업 책상에서 일하고, 보고서만 가져오는 동료 [메인 책상] ←— 보고서 —— [서브에이전트 책상] 깨끗 유지 파일 조사 수행

개념 구분: 서브에이전트는 실행 메커니즘(별도 컨텍스트에서 작업 위임)이고,
커스텀 에이전트는 그 서브에이전트에게 "역할과 원칙"을 부여하는 정의 파일

Claude Code의 커스텀 에이전트

커스텀 에이전트 = .claude/agents/{이름}.md .claude/ └── agents/ ├── code-reviewer.md ← 코드 리뷰 전문가 ├── test-writer.md ← 테스트 작성 전문가 └── doc-writer.md ← 문서 작성 전문가

사용법

대화에서 에이전트 이름을 언급하면
해당 정의를 참조하여 실행

예시

code-reviewer 에이전트로 TaskForm.tsx를 리뷰해줘

CLAUDE.md처럼 git에 커밋하면, 팀 전체가 같은 에이전트를 공유할 수 있다

에이전트 정의 파일 해부

--- ← YAML frontmatter (필수) name: code-reviewer ← 에이전트 식별 이름 description: 코드 품질과 보안 관점에서 리뷰 --- # code-reviewer 코드 품질과 보안 관점에서 리뷰하는 에이전트. ## 핵심 역할 ← "무엇을" (좁게!) 지정된 파일의 코드를 분석하여 이슈를 보고한다. ## 작업 원칙 ← "어떻게" (구체적으로!) 1. 버그 가능성이 가장 높은 패턴 우선 검사 2. 보안 이슈 반드시 확인 3. CLAUDE.md 규칙 준수 여부 확인 ## 출력 형식 ← 결과물 (형식까지!) - 이슈 목록 (심각도: 높음/중간/낮음)

좋은 에이전트 정의 3원칙

1. 역할을 좁게

✓ "코드 품질과 보안 관점에서 리뷰"

✗ "코드를 분석하고 수정하고 테스트하고 문서화"

2. 원칙을 구체적으로

✓ "버그 가능성이 가장 높은 패턴을 우선 검사"

✗ "코드를 잘 분석해라"

3. 출력 형식을 명시

✓ "이슈 목록 — 심각도: 높음/중간/낮음"

✗ "결과를 보고해라"

모든 걸 하는 에이전트 1개 < 전문화된 에이전트 3개

에이전트 분리 기준

✓ 분리하면 좋은 경우

  • 전문 지식이 다름 (보안 vs 성능 vs 품질)
  • 병렬 실행 가능 (FE + BE + 테스트)
  • 컨텍스트가 분리됨 (서로 다른 파일 세트)
  • 재사용 가능 (다른 프로젝트에서도 동일 역할)

✗ 분리하지 않아도 되는 경우

  • 작업이 단순하고 한 세션으로 충분
  • 에이전트 간 통신 오버헤드 > 작업 자체
  • 컨텍스트를 공유해야 하는 밀접한 작업

3명의 집중된 팀 > 5명의 산만한 팀

2-3개로 시작해서 필요하면 확장하는 게 정석

파이프라인 (순차)

A → B → C
앞 단계 결과를 다음이 이어받음

팬아웃 (병렬)

A → B + C + D
독립 작업을 동시에 실행

생성-검증 (피드백 루프)

A ↔ B
기준 미달이면 재시도
