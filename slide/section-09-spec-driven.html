R.P.I — 3단계 워크플로우

1 Research (조사)

기존 코드 읽기, 관련 파일 파악 — 사실(Fact) 기반 컨텍스트 수집

2 Plan (계획)

뭘 바꿀지, 어떤 순서로, 완료 조건은 뭔지 — 인간이 검토 후 승인

3 Implement (구현)

승인된 계획을 기계적으로 실행 — 각 체크포인트마다 테스트/빌드 검증

각 단계는 별도 컨텍스트에서 실행 (조사 → /clear → 계획 → /clear → 구현)

Spec Driven — 완료를 먼저 정의하라

# spec: 필터 버그 수정

## 목표
"완료" 필터 선택 시 completed 상태의 업무만 표시

## 수락 기준
- [ ] 필터 "완료" → completed 상태만 표시
- [ ] 필터 "진행 중" → in_progress 상태만 표시
- [ ] 기존 테스트 깨지지 않음 (npm test 통과)
- [ ] 새 테스트 최소 2개 추가

## 제약 조건
- TaskList.tsx만 수정
- 기존 API 변경 금지

Spec = 소스 오브 트루스. 코드 = 파생 산출물.

좋은 Spec의 6가지 영역

Addy Osmani (Google)

  • 명령어 — 빌드/테스트/린트 실행 방법
  • 테스트 — 프레임워크, 커버리지 기준
  • 프로젝트 구조 — 파일 위치 규칙
  • 코드 스타일 — 네이밍, 포매팅, 타입
  • Git 워크플로우 — 브랜치, 커밋 규칙
  • 금지 사항 — 절대 하면 안 되는 것

3단계 경계

  • Always do — 항상 해야 하는 것
  • Ask first — 확인 후 진행
  • Never do — 절대 하면 안 되는 것

주의: 지시가 많아질수록 준수율이 떨어짐 → 핵심만, 짧게

## 작업 방식
- 구현 전에 반드시 계획 먼저
- 3줄 이상 수정 시 계획 필수
- "완료 조건" + "제약 조건" 포함

## 검증
- 구현 후 테스트 실행
- 테스트 없으면 먼저 작성

Step 2: 계획 (완료/제약 조건)

Spec Driven 3줄 요약

spec = 수락 기준 + 제약 조건
